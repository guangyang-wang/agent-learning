# 提示词工程（Prompt Engineering）

> **提示词工程**：通过优化提示词，让模型的输出更符合业务需要的过程。
> 核心公式：**好提示词 = 定角色 + 给任务 + 提要求**
> 把这三步写清楚，AI 的输出质量会明显提升。

---

## 第一步：定角色（给 AI 一个身份）

先告诉 AI「你是谁」，让它进入对应的知识领域、语气和视角。

- 角色决定 AI 用**什么知识**、**什么口吻**、**站在谁的角度**回答。
- 例：让 AI 当「资深 Python 工程师」vs「小学老师」，讲解同一个知识点，深度和语气完全不同。

| 写法 | 效果 |
|------|------|
| ❌ 直接问 | 「帮我解释递归」 | 通用、笼统 |
| ✅ 定角色 | 「你是一名有 10 年经验的 Java 工程师，正在带一个转学 Python 的新手」 | 会结合 Java 类比、照顾新手 |

常见角色举例：
- 资深后端工程师 / 前端工程师
- 面试官（模拟面试）
- 产品经理 / 技术文档写手
- 某领域专家（法律、医学、金融……）
- 翻译 / 校对 / 摘要助手

---

## 第二步：给任务（说清楚要做什么）

用一句明确的指令描述任务本身。要点：

1. **动词开头、指令明确**：`写` / `解释` / `总结` / `翻译` / `改写` / `找出 bug`
2. **有具体对象和范围**：做什么、针对什么
3. **必要背景信息**：任务相关的上下文

| 写法 | 效果 |
|------|------|
| ❌ 模糊 | 「帮我看看这段代码」 | 不知道看什么、怎么改 |
| ✅ 明确 | 「找出下面这段 Python 代码里的 bug，并解释为什么出错」 | 任务 + 对象 + 期望都清楚 |

---

## 第三步：提要求（约束输出的样子）

对**输出结果**提要求，让回答符合你的预期。常见维度：

| 要求维度 | 例子 |
|----------|------|
| 输出格式 | 「用 Markdown 表格」/「分点列出」/「给 JSON」 |
| 长度 | 「控制在 200 字以内」/「一段话总结」 |
| 语言/语气 | 「用中文」/「口语化」/「正式」 |
| 深度 | 「讲给零基础」/「只给结论，不要展开」 |
| 风格 | 「类比 Java 来讲」/「举例说明」 |
| 约束 | 「不要用专业术语」/「代码要加注释」 |

---

## 完整模板（照着填）

```text
【角色】
你是一名 ____（身份/领域专家）。

【任务】
请 ____（动词 + 具体做什么）。

【要求】
- 格式：____
- 长度：____
- 语言/语气：____
- 其他约束：____
```

### 实际例子

```text
你是一名资深 Python 工程师，正在带一个从 Java 转过来的新手。

请解释「列表推导式 list comprehension」是什么、怎么用。

要求：
- 用中文，面向有 Java 基础的人
- 类比 Java 的 Stream / for 循环来讲
- 给出 3 个由浅入深的代码例子，每个都加注释
- 最后用一个表格对比 Python 和 Java 的写法
```

## 系统提示词的组成（系统化写法）

System Prompt 一般按**固定顺序**包含四部分：

| 顺序 | 部分 | 英文 | 作用 |
|------|------|------|------|
| 1 | 身份角色 | Identity | AI 的职责、沟通风格、总体目标 |
| 2 | 指令说明 | Instructions | 该怎么做、遵循什么规则、绝对不能做什么 |
| 3 | 对话示例 | Examples | 给「输入 → 期望输出」样例，让模型照着学 |
| 4 | 背景信息 | Context | 额外资料（如 RAG 知识库），供生成时参考 |

编写时可用 **Markdown（标题/列表）+ XML 标签（`<tag>...</tag>`）** 的组合来划分逻辑边界：Markdown 负责层级结构，XML 负责圈定一段内容的起止。

```text
# Identity                      ← Markdown 标题，划分区块
你是……（角色）

# Instructions
- 只能输出一个单词
- 不要加任何解释

# Examples
<product_review id="example-1">   ← XML 标签，圈定一段样例
这家店太好了！
</product_review>
<assistant_response id="example-1">
Positive
</assistant_response>
```

> 对应关系：这个「四部分」其实就是前面「三步法」的细化——`Identity`≈定角色，`Instructions`≈给任务 + 提要求，`Examples`≈进阶技巧里的少样本示例，`Context` 是新增的背景资料。

---

## 进阶技巧（在「三步」基础上叠加）

| 技巧 | 说明 | 例子 |
|------|------|------|
| 少样本示例 Few-shot | 给 1~2 个「输入→期望输出」的样例，让 AI 照着学 | 「像这样把 JSON 转成表格：{输入} → {输出}」 |
| 分步思考 | 让 AI 先分析再回答，减少跳步 | 「先列思路，再给代码」 |
| 限定反例 | 告诉它「不要怎么做」 | 「不要用专业术语」「不要超过 100 行」 |
| 追问式拆解 | 任务太复杂时，拆成多轮 | 「先给方案，我确认后再写代码」 |
| 指定输出结构 | 要程序化处理时，让它输出固定结构 | 「输出 JSON，字段为 name/age/city」 |

## 结构化输出（让模型按固定格式回答）

模型擅长自然语言，但程序处理**结构化数据**更方便。结构化输出就是让模型按固定结构返回，方便代码解析。有两种方式：

### 方式一：靠提示词（自己写格式要求）

在提示词里直接要求模型输出 JSON：

```python
system_prompt = """
# 指令
- 请务必以 JSON 格式输出，不要加任何 markdown 样式。

# 示例
user: 月球的首都是什么？
assistant:
{
    "name": "月华市（Lunaria）",
    "location": "位于月球正面赤道附近…",
    "vibe": "冷冽、高效、革新",
    "economy": "氦-3能源开采…"
}
"""

response = agent.invoke({"messages": [HumanMessage("金星的首都是什么?")]})
print(response["messages"][-1].content)   # 拿到的是 JSON 字符串，还得自己 json.loads
```

> 缺点：模型可能不听话（偶尔加 markdown、字段乱写），而且拿到的是**字符串**，还得自己 `json.loads` 解析，容易出错。

### 方式二：靠 Model（传一个 pydantic 类，推荐）

LangChain 里更简单的做法：**定义一个 pydantic 类描述结构，把它传给 `response_format`**，LangChain 自动帮你改造提示词 + 解析结果：

```python
from pydantic import BaseModel

class CapitalInfo(BaseModel):   # ← 定义「输出长什么样」
    name: str
    location: str
    vibe: str
    economy: str

agent = create_agent(
    model="deepseek-chat",
    system_prompt="你是一个科幻作家…",
    response_format=CapitalInfo,   # ← 传类（不是实例）
)

response = agent.invoke({"messages": [HumanMessage("月球的首都是什么?")]})

city = response["structured_response"]   # ← 直接拿到对象，不用自己解析
print(city.name, city.location)          # city.name → '月宫'
```

| 对比 | 方式一（提示词） | 方式二（pydantic 类） |
|------|------|------|
| 谁来保证格式 | 模型自觉 | LangChain 框架强制 |
| 拿到的东西 | 字符串（要 `json.loads`） | 现成的 pydantic 对象 |
| 出错风险 | 高（可能不听话） | 低（字段类型都校验好了） |

> **本质**：`response_format` 把一个 pydantic 类当「输出契约」传给模型。LangChain 会把这个类自动转成工具（你会看到一条 `ToolMessage(name='CapitalInfo')`），让模型按字段填值，再反序列化回对象。我们只需 `response["structured_response"]` 就能拿到现成对象。

### 与 Java 类比

| LangChain | Java 类比 | 说明 |
|------|------|------|
| pydantic `BaseModel` 类 | POJO / DTO 类 | 用字段 + 类型描述数据结构 |
| `response_format=CapitalInfo` | 声明方法返回类型 `CapitalInfo` | 提前定好「输出契约」 |
| `response["structured_response"]` | Jackson `readValue(json, CapitalInfo.class)` | 自动把数据反序列化成对象 |

## 与你代码的关系

在 `python代码/deepseek.py` 里，`messages` 已经体现了「定角色」：

```python
messages=[
    {"role": "system", "content": "You are a helpful assistant"},  # ← 定角色
    {"role": "user",    "content": "请你用python帮我写一个游戏"},  # ← 给任务（缺「提要求」）
],
```

- `system` 消息 → 对应「定角色」，定全局身份/规则
- `user` 消息 → 对应「给任务 + 提要求」

可以改进成更完整的提示词：

```python
messages=[
    {"role": "system", "content": "你是一名 Python 游戏开发专家。"},  # 定角色
    {"role": "user", "content": (                                    # 给任务 + 提要求
        "用 Python 写一个命令行猜数字游戏。\n"
        "要求：\n"
        "- 只用一个 .py 文件，代码加中文注释\n"
        "- 包含输入校验，猜错时提示「大了/小了」\n"
        "- 猜对后显示猜了多少次"
    )},
],
```

## 速查（一页纸）

1. **定角色** → 告诉 AI「你是谁」（身份/领域/语气）
2. **给任务** → 动词开头 + 明确对象（做什么）
3. **提要求** → 约束输出（格式/长度/语言/风格）
4. 进阶：少样本示例、分步思考、限定反例、指定结构
5. 代码映射：`system` = 定角色，`user` = 给任务 + 提要求
6. **系统提示词四部分**：Identity(角色) → Instructions(指令) → Examples(示例) → Context(背景)
7. **结构化输出**：定义 pydantic 类 + `create_agent(response_format=类)`，用 `response["structured_response"]` 直接拿对象
