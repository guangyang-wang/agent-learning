# 网络知识复习汇总

> 一条主线串起所有内容：**域名 → DNS 解析 → IP → 建立连接（TCP/HTTPS）→ 收发数据**。
> 调用 AI API（如 `api.anthropic.com`、`api.openai.com`）本质就是走完整条链路。

---

## 第一部分：网络模型与协议（总览分层）

### 为什么分层
把「发一条消息」拆成多层，好处：
- 每层职责单一，独立设计和维护
- 层与层之间只靠固定接口交互，可替换（网线换 WiFi 不影响上层）
- 出问题能按层定位

### OSI 七层模型（理论）

口诀：**「应表会传网数物」**

| 层 | 名称 | 作用 | 常见协议/设备 |
|----|------|------|---------------|
| 7 | 应用层 | 为用户提供网络服务 | HTTP、DNS、FTP、SMTP |
| 6 | 表示层 | 数据格式转换、加密、压缩 | TLS 加密、编码 |
| 5 | 会话层 | 建立/管理/终止会话 | — |
| 4 | 传输层 | 端到端（进程到进程）通信 | **TCP、UDP** |
| 3 | 网络层 | 寻址、路由（找到目标主机） | **IP**、ICMP、路由器 |
| 2 | 数据链路层 | 相邻节点间传帧 | 以太网、MAC 地址、交换机 |
| 1 | 物理层 | 传输比特流（0/1） | 网线、光纤、集线器 |

> OSI 是**理论模型**，实际互联网用的是简化后的 TCP/IP 模型。

### TCP/IP 四层模型（实际）

| TCP/IP 层 | 对应 OSI | 常见协议 |
|-----------|----------|----------|
| 应用层 | 5~7 层 | HTTP、HTTPS、DNS、SSH |
| 传输层 | 4 层 | TCP、UDP |
| 网络层（网际层） | 3 层 | IP、ICMP、ARP |
| 网络接口层 | 1~2 层 | 以太网、WiFi |

> 教学里也常讲**五层模型**：应用层 / 传输层 / 网络层 / 数据链路层 / 物理层（把网络接口层拆回两层），最直观。

### 各层核心协议速览

| 层 | 管什么 | 关键协议 |
|----|--------|----------|
| 应用层 | 「发什么」 | HTTP/HTTPS、DNS、SSH、SMTP |
| 传输层 | 「怎么可靠地传」 | TCP（可靠）、UDP（快） |
| 网络层 | 「往哪传」 | IP（寻址路由）、ICMP（ping）、ARP（IP→MAC） |
| 链路/物理层 | 「底层怎么传」 | 以太网、MAC 地址、网线/光纤 |

### TCP vs UDP

| 对比 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠、有序、丢包重传 | 不可靠、不保证到达 |
| 速度 | 慢 | 快 |
| 适用场景 | 网页、文件下载、邮件 | 视频通话、直播、游戏、DNS 查询 |

> 记法：TCP 像「挂号信」（确认签收），UDP 像「明信片」（发出去不管）。

### 数据封装（重点）

数据从上层往下传，每层加自己的「头部」，接收端再逐层拆掉：

```
发送端（封装，从上往下）：
  数据
  → [TCP头 | 数据]                          # 传输层加 TCP 头
  → [IP头 | TCP头 | 数据]                   # 网络层加 IP 头
  → [帧头 | IP头 | TCP头 | 数据 | 帧尾]      # 数据链路层加帧

接收端（解封装，从下往上）：
  逐层拆掉对应的头，最后还原出原始数据
```

> 就像寄包裹：数据是信，每层包一层信封，写不同的地址信息，到了目的地再一层层拆。

## 第二部分：网络基础（IP、域名、DNS）

### IP 地址

IP（Internet Protocol）地址是**网络中设备的唯一标识**，用于定位一台机器、让它能收发数据。

- **IPv4**：32 位，点分十进制 `192.168.1.1`，范围 `0.0.0.0 ~ 255.255.255.255`（约 43 亿个，已基本耗尽）
- **IPv6**：128 位，8 组十六进制 `2001:0db8:85a3:...:7334`，为解决 IPv4 耗尽而生

#### 公网 IP vs 私网 IP

| 类型 | 说明 | 例子 |
|------|------|------|
| 公网 IP | 全球唯一，互联网上可直接访问 | `8.8.8.8`（Google DNS） |
| 私网 IP | 局域网内使用，不能直接上公网，靠 NAT 转换 | `192.168.x.x` |

私网地址段（保留段）：
- A 类：`10.0.0.0 ~ 10.255.255.255`
- B 类：`172.16.0.0 ~ 172.31.255.255`
- C 类：`192.168.0.0 ~ 192.168.255.255`（家用路由器最常见）

#### 特殊地址

| 地址 | 含义 |
|------|------|
| `127.0.0.1` / `localhost` | 本机回环地址（指向自己） |
| `0.0.0.0` | 所有地址 / 未知地址 |
| `255.255.255.255` | 广播地址 |

### 端口（Port）

IP 定位**主机**，端口定位主机上的**具体服务/进程**，范围 `0 ~ 65535`。
同一台服务器可同时跑多个服务，靠端口区分；`IP:端口` 才能精确定位一个程序。

| 端口 | 服务 |
|------|------|
| `80` | HTTP |
| `443` | HTTPS |
| `22` | SSH |
| `21` | FTP |
| `3306` | MySQL |
| `6379` | Redis |
| `8080` / `8000` | 常见开发/测试端口 |

> 浏览器访问 `http://example.com` 默认连 `:80`，`https://` 默认连 `:443`，端口被省略了。

### 域名（Domain）

IP 是数字难记，域名是 IP 的**易记别名**，像「电话簿里的名字 vs 电话号码」。

#### 域名结构（从右到左层级）

```
api.example.com
 │    │      │
 │    │      └── 顶级域名 TLD（.com / .org / .cn / .edu）
 │    └───────── 二级域名（你注册的 example.com）
 └────────────── 三级域名 / 子域（api、www、blog 等）
```

| 层级 | 示例 | 说明 |
|------|------|------|
| 顶级域名 TLD | `.com` `.org` `.cn` | 最右，代表类型或地区 |
| 二级域名 | `example` | 真正注册买下的名字 |
| 子域 | `api` `www` | 可自由划分，指向不同服务 |

#### 域名与 IP 的关系
- 一个域名 → 多个 IP（负载均衡 / 就近访问）
- 一个 IP → 多个域名（一台服务器托管多个站）
- 域名只是入口，最终通信还是靠 IP

### DNS 解析

DNS（Domain Name System）是**分布式数据库**，负责把**域名翻译成 IP**，就像电话簿查号码。

#### 解析流程（重点）

访问 `www.example.com` 时依次查询：

```
域名 → 浏览器缓存 → hosts 文件 → 本地DNS → 根服务器 → 顶级域服务器 → 权威域服务器 → 得到 IP
```

1. **浏览器缓存** —— 之前查过就直接用
2. **系统 hosts 文件** —— `C:\Windows\System32\drivers\etc\hosts`（或 `/etc/hosts`），手动映射优先
3. **本地 DNS 服务器**（运营商提供，递归查询）
4. **根域名服务器** —— 返回「`.com` 该找谁」
5. **顶级域名服务器** —— 返回「`example.com` 该找谁」
6. **权威域名服务器** —— 返回 `www.example.com` 的真实 IP
7. 拿到 IP 后建立连接

#### 递归查询 vs 迭代查询

| 方式 | 说明 |
|------|------|
| 递归查询 | 客户端只问一次，本地 DNS 负责全程查到结果返回 |
| 迭代查询 | 本地 DNS 一级一级问，每次得到「下一步问谁」的指引 |

#### 常见 DNS 记录类型

| 类型 | 作用 |
|------|------|
| `A` | 域名 → IPv4 地址 |
| `AAAA` | 域名 → IPv6 地址 |
| `CNAME` | 别名 → 另一个域名（如 `www` → 主域名） |
| `MX` | 邮件服务器 |
| `NS` | 该域名的 DNS 服务器 |
| `TXT` | 文本记录（域名验证、SPF 等） |

#### 手动查询 DNS

```bash
ping www.example.com        # 测试连通性，会显示解析出的 IP
nslookup www.example.com    # 查询 DNS（Windows）
dig www.example.com         # 查询 DNS（Linux / Mac）
ipconfig /flushdns          # 清空 DNS 缓存（Windows）
```

## 第三部分：HTTP 与 HTTPS（应用层协议）

### HTTP 协议

HTTP（HyperText Transfer Protocol）超文本传输协议，**应用层**协议，基于 TCP，采用**请求-响应**模型：
- 客户端发起请求 → 服务器返回响应
- **无状态**：每次请求独立，服务器不记得上次（靠 Cookie / Session / Token 保持状态）

#### 请求结构

```
GET /index.html HTTP/1.1        ← 请求行：方法 路径 版本
Host: www.example.com           ← 请求头（键值对）
User-Agent: Mozilla/5.0
Accept: text/html

                                ← 空行（分隔）
请求体（可选，GET 一般没有）     ← body
```

#### 响应结构

```
HTTP/1.1 200 OK                 ← 状态行：版本 状态码 原因
Content-Type: text/html         ← 响应头
Content-Length: 123

                                ← 空行
<html>...</html>                ← 响应体
```

#### HTTP 方法

| 方法 | 作用 | 对应 CRUD |
|------|------|-----------|
| `GET` | 获取资源 | Read |
| `POST` | 提交/创建数据 | Create |
| `PUT` | 整体更新 | Update |
| `PATCH` | 部分更新 | Update |
| `DELETE` | 删除 | Delete |
| `HEAD` | 只取响应头 | — |

> 最常用的是 `GET`（取数据）和 `POST`（提交数据）。

#### 状态码

| 状态码 | 类别 | 常见值 |
|--------|------|--------|
| `2xx` | 成功 | `200 OK`、`201 Created` |
| `3xx` | 重定向 | `301` 永久、`302` 临时、`304` 缓存 |
| `4xx` | 客户端错误 | `400` 参数错、`401` 未认证、`403` 禁止、`404` 不存在、`429` 限流 |
| `5xx` | 服务器错误 | `500` 内部错误、`502` 网关、`503` 不可用 |

> 记法：4 开头是「你的错」，5 开头是「服务器的错」。

### HTTPS 协议

HTTPS = **HTTP + SSL/TLS 加密层**。HTTP 是明文传输，HTTPS 对数据加密后再传。

| 项 | HTTP | HTTPS |
|----|------|-------|
| 端口 | `80` | `443` |
| 加密 | 明文（可被窃听） | SSL/TLS 加密 |
| 安全性 | 不安全 | 防窃听、防篡改、防冒充 |
| 证书 | 无 | 需 CA 证书验证身份 |
| 速度 | 略快 | 略慢（多一次加密握手） |

HTTPS 解决 HTTP 明文传输的三个问题：
- **加密** → 防窃听
- **完整性校验** → 防篡改
- **CA 证书** → 防冒充（证明「你就是 example.com」）

## 第四部分：与 AI 应用的关系 + 排错速查

### 调用 AI API 的完整链路

```python
import requests

resp = requests.post(
    "https://api.anthropic.com/v1/messages",   # HTTPS + 域名
    headers={"x-api-key": "...", "anthropic-version": "..."},
    json={"model": "claude-sonnet-4-6", "messages": [...]},
)
```

这行代码背后发生的：

```
代码请求 api.anthropic.com
  → DNS 解析 → 得到服务器 IP
  → 连 IP 的 443 端口（HTTPS）
  → 传输层 TCP 握手（保证可靠送达）
  → 发 POST 请求 + JSON body + API key
  → 服务器返回状态码 + 响应体
```

### 按层定位问题

| 出错环节 | 症状 | 可能原因 |
|----------|------|----------|
| DNS 解析失败 | 域名解析不了 | 域名错、DNS 服务器问题、被墙 |
| 网络层 | ping 不通、路由不通 | 防火墙、网络不通 |
| 传输层 | 连接超时、被重置 | TCP 握手失败、代理问题 |
| 应用层 | `404` `401` | 路径/参数/认证错误 |
| 端口不通 | 连不上服务 | 服务未启动、端口被占用 |

### 看状态码判断 API 问题

| 状态码 | 含义 |
|--------|------|
| `200` | 成功 |
| `401` | API key 错误 / 未授权 |
| `429` | 请求太频繁，被限流 |
| `500` / `502` | 服务器端故障 |

## 复习要点速查（一页纸）

1. **分层**：应用层(HTTP/DNS) → 传输层(TCP/UDP) → 网络层(IP) → 链路层(以太网/MAC) → 物理层
2. **IP**：主机标识；**端口**：进程标识，`IP:端口` 精确定位一个服务
3. **DNS**：域名 → IP 的「电话簿」，解析顺序「缓存 → hosts → 本地DNS → 根 → 顶级 → 权威」
4. **TCP** 可靠但慢（挂号信），**UDP** 快但不可靠（明信片）
5. **封装**：每层往下加头，接收端逐层拆头
6. **HTTP**：应用层，请求-响应模型，无状态；方法 GET/POST，状态码 2xx/3xx/4xx/5xx
7. **HTTPS** = HTTP + TLS，443 端口，加密/校验/证书解决窃听/篡改/冒充
8. **AI API 链路**：域名 → DNS → IP → 443 端口 → TCP → HTTP 请求 → 响应
