# Agent 开发学习路线

> 目标项目：**简历优化 / 求职 Agent**（LangGraph 多 Agent + RAG）
> 基线：Java 后端背景，Python 已过容器/函数/类/异常/模块

## 阶段 1：Python 补齐（面向 Agent 的缺口）

- [ ] 装饰器 `@`（`@register_tool`、FastAPI 路由）→ `代码/decorator.py`
- [ ] Pydantic `BaseModel`（工具参数 schema、结构化输出）→ `代码/pydantic_model.py`
- [ ] asyncio 异步（并发调多个模型/工具）→ `代码/asyncio_demo.py`
- [ ] 生成器 `yield`（SSE 流式输出）→ `代码/yield_stream.py`
- [ ] FastAPI（Agent 后端标配）→ `代码/fastapi_demo.py`

**验证**：能写 FastAPI 接口，接收 Pydantic 模型，返回 SSE 流式结果。

## 阶段 2：LLM 调用 + Prompt + 结构化输出

- [ ] OpenAI 兼容 API 调用（DeepSeek），四种消息结构
- [ ] 结构化输出（JSON mode + Pydantic 解析）
- [ ] Prompt 基础：系统提示词 / few-shot / CoT
- [ ] 练习：简历技能抽取 → 稳定返回 `{skills, years}`

**验证**：同一段简历跑 10 次，JSON 解析 10/10 成功。

## 阶段 3：Agent 核心——手写 ReAct 循环（地基，别跳过）

- [ ] 手写 Agent Loop（~50 行 `while` + stop_reason）
- [ ] Tool 设计：`name` + `description` + `parameters` schema
- [ ] Function Calling：模型输出 `tool_call` 而非文本
- [ ] 容错：JSON 失败重试 / `max_steps` 熔断 / 超时降级

**验证**：跑通"算 3 个订单总价 + 搜索公司信息"这类多工具连续调用。

## 阶段 4：RAG 全链路（简历 Agent 的灵魂）

- [ ] 文档解析：PDF / DOCX 简历（PyMuPDF / python-docx）
- [ ] 分块 Chunking（token 阈值 + overlap 10~20%）
- [ ] Embedding（BGE / 通义）
- [ ] 混合检索：BM25 + 向量，RRF 融合
- [ ] 重排序：Bi-Encoder vs Cross-Encoder
- [ ] 向量库 Chroma

**验证**：简历知识库能检索到正确片段，能讲清"为什么混合检索 + 重排"。

## 阶段 5：LangGraph 多 Agent

- [ ] State / Node / Edge（`TypedDict` 状态机）
- [ ] 条件分支路由
- [ ] Supervisor 模式（planner / JD 分析 / 简历生成 / 面试模拟）
- [ ] Human-in-the-loop（简历生成后人工审批）

**验证**：JD + 简历输入 → 端到端产出定制简历 + 差距报告 + 模拟面试题。

## 阶段 6：工程化 + 评估（差异化亮点）

- [ ] SSE 流式输出（FastAPI 逐 token 返回）
- [ ] 评估：RAGAS + LLM-as-Judge，建立准确率/延迟/成本指标
- [ ] 可观测：Langfuse 追踪 token 消耗 / 耗时 / 失败
- [ ] Docker 部署
- [ ] MCP 集成（加分）

**验证**：部署后能说出"准确率提升 X% / 单次成本 Y 元 / P99 延迟 Z 秒"。
