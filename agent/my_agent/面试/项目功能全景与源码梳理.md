## 一、总体结论与技术栈

### 1.1 技术栈

| 层 | 实现 |
|---|---|
| 编排 | LangGraph（手写 StateGraph、ConditionalEdges，未用 `create_react_agent` 等预封装） |

| 前端 | Vue 3 + Element Plus + markdown-it / highlight.js / DOMPurify |

`开发任务清单.md` 里阶段 0–3 打勾、4–8 未打勾，与源码实际状态完全吻合：

- **已完成**：单 Agent ReAct、RAG、短期记忆、Plan-and-Execute、FastAPI/Vue、Docker 部署；

## 二、全局状态与配置

### 2.1 AgentState（`src/agent/state.py:27`）

整张图的共享上下文对象（Java 类比：流程上下文 DTO）。

| 字段 | 作用 | 关键设计 |
|---|---|---|
| `user_input` | 用户原始输入 | 本轮问题的起点 |
| `messages` | 对话消息（短期记忆载体） | `add_messages` reducer，追加而非覆盖 |
| `user_names` | 每轮提问人 | `operator.add`，与用户消息顺序一一对应 |
| `plan_messages` | 规划会话的请求历史 | 单独开通道，避免混进 chat 会话列表，也避免 chat/plan 共用 thread_id 时状态污染（`state.py:43-49`） |
| `plan_names` | 规划会话每轮提问人 | `operator.add` |
| `iteration_count` | ReAct 循环计数器 | 为阶段 6 防死循环预留（目前未真正使用） |
| `plan` | 任务计划 | `{id, desc, agent, deps, status}` |
| `current_subtask_id` | 当前执行的子任务 id | dispatcher 更新 |
| `subtask_results` | 子任务产出 `{id: text}` | writer/reviewer 汇总的依据 |
| `replan_count` | 局部重规划次数 | 用 `MAX_REPLAN` 上限兜底 |

## 三、单 Agent ReAct 对话（`/chat`）

**源码**：`src/agent/graph/react_graph.py`、`src/agent/graph/nodes.py`

### 3.1 图结构

```
START -> agent --(有 tool_calls)--> tools -> agent
                 --(无 tool_calls)--> END
```

### 3.2 核心实现

| 组件 | 位置 | 作用 |
|---|---|---|
| `make_agent_node` | `react_graph.py:20-44` | 把全部注册工具 `bind_tools` 给 LLM；system prompt 只在本次调用前置，不写回 State，避免循环中重复堆积 |
| `should_continue` | `react_graph.py:51-64` | 只看最后一条 AIMessage 是否带 `tool_calls`，决定继续调工具还是结束 |
| `tools_node` | `nodes.py:14-49` | 逐个执行 tool_calls，把结果包成 ToolMessage 回填；未知工具、工具异常都转成文本回传，**单工具失败不中断循环** |
| `build_react_graph` | `react_graph.py:67-101` | 支持传入 `checkpointer`（短期记忆）和 `system_prompt`（角色人格），后者被 Plan 图复用 |

### 3.3 复用点

`system_prompt` 参数让同一个 ReAct 循环扮演 knowledge / code / writer / reviewer，实现「1 底座 + 2 编排」中「上层编排复用底层推理」。

## 四、工具系统（安全分级 + 安全求值）

**源码**：`src/agent/tools/registry.py`、`src/agent/tools/safe_tools.py`

### 4.1 已注册的 3 个安全工具（`registry.py:50-55`）

| 工具 | 功能 | 实现要点 |
|---|---|---|
| `calculator` | 数学表达式计算 | **不用裸 eval**，`ast.parse` 后只放行白名单节点/函数（`safe_tools.py:63-83`），杜绝任意代码执行 |
| `get_current_time` | 当前日期时间 | `safe_tools.py:88-91` |
| `rag_search` | 课件检索 | 调 `retrieve_with_fallback`，检索不到时明确返回「无课件依据」（`safe_tools.py:96-116`） |

### 4.2 安全分级

`ToolLevel` 预留 `SAFE / DANGEROUS` 两级；高危工具（代码运行、联网、写文件）目前仍是占位（`dangerous_tools.py`），拦截逻辑未实现。

### 4.3 calculator 的安全求值思路

1. `ast.parse(expression, mode="eval")` 得到 AST；
2. 递归求值，只放行：数字常量、四则/幂/取模等二元运算、正负号、白名单数学函数；
3. 其余节点（属性访问、导入、任意函数调用）一律抛错。

Java 类比：相当于不用 `ScriptEngine.eval()`，而是自己做语法树解释器，只解释允许的语法。

## 五、Plan-and-Execute 复杂任务（`/plan`）

**源码**：`src/agent/graph/plan_graph.py`，项目里完成度最高的部分。

### 5.1 图结构（`plan_graph.py:566-595`）

```
START -> planner -> dispatcher --(execute)--> executor -> dispatcher
                              --(end)-------> END
                              --(replan)----> replan -> dispatcher
```

### 5.2 规划器 planner

| 能力 | 实现 |
|---|---|
| 提示词约束 | 只输出 JSON 数组；1~8 步；agent 限定 `knowledge / code / writer / reviewer`（`plan_graph.py:57-89`） |
| 容错解析 | 去掉 markdown 围栏 → 截取第一个 `[` 到最后一个 `]` → `json.loads`（`plan_graph.py:92-103`） |
| 结构校验 | 步骤数、id 唯一、desc/agent/status 合法、依赖存在且非自依赖、Kahn 拓扑排序检测环（`plan_graph.py:106-189`） |
| 失败重试 | 把错误回喂给 LLM，最多 `MAX_PLAN_RETRIES=3` 次（`plan_graph.py:210-231`） |
| 确定性兜底 | 仍失败则用固定三步计划：knowledge → code → writer（`plan_graph.py:197-207`） |
| 跨轮记忆 | 把本会话此前的请求（`plan_messages[:-1]`）作为上下文，让 planner 理解「它 / 刚才那个」 |
| 执行态重置 | 每轮进入 planner 都重置 `subtask_results` / `replan_count`，防止上一轮产出污染本轮（`plan_graph.py:234-248`） |

### 5.3 调度器 dispatcher

- `_next_runnable`（`plan_graph.py:253-270`）：按声明顺序扫描，返回第一个「pending 且所有 deps 都 success」的任务；
- `dispatch_route`（`plan_graph.py:295-316`）：
  1. 有 running → `execute`；
  2. 没有 pending → `end`；
  3. 有 pending 但依赖失败卡死 → `replan`。

### 5.4 执行器 executor：复用 ReAct 底座

| 能力 | 实现 |
|---|---|
| 四个角色 prompt | `SUBTASK_SYSTEM_PROMPTS`（`plan_graph.py:323-343`） |
| 按角色缓存图 | `lru_cache` 最多 4 张 ReAct 图（`plan_graph.py:369-377`） |
| 汇总前置结果 | 子任务输入带总任务 + 本步骤 + 所有已完成前置结果（`plan_graph.py:346-366`） |
| 隔离会话 | 子任务图不接 checkpointer，避免污染父会话（`plan_graph.py:380-395`） |
| 失败处理 | 捕获异常，标记 `failed` 并把 error 写进计划项，交给 replan（`plan_graph.py:398-424`） |

### 5.5 局部重规划 replan

1. 只针对失败子任务让 LLM 产出修正版，**id / deps 不变**，desc / agent 可变；
2. 校验修正结果覆盖全部失败 id（`plan_graph.py:461-487`）；
3. 成功子任务原封不动，失败项重置为 pending；
4. `MAX_REPLAN=2`，超限则放弃剩余未完成子任务，保留已成功部分收尾（`plan_graph.py:522-563`）。

### 5.6 最终输出

`service.final_output`（`service.py:104-118`）：

- 优先取「没有其他任务依赖它」的 sink 子任务产出；
- sink 没产出时，回退到最后一个有产出的子任务。

## 六、RAG 私有知识库

**源码**：`src/agent/rag/`

完整链路：**PDF 字节 → 页文本 → chunk → 向量 → Chroma → 检索/回退**。

### 6.1 各环节实现

| 环节 | 位置 | 实现 |
|---|---|---|
| 解析 | `loader.py:24-45` | pypdf 逐页提取；单页失败/为空跳过；整份提不出文本抛 `ValueError`（接口转 400） |
| 分块 | `splitter.py:125-149` | **手写递归字符分割**：分隔符按段落 → 换行 → 中文标点 → 空格逐级降级，保留分隔符，再按 `chunk_size=500 / overlap=50` 合并重叠 |
| 向量化 | `embedding.py:44-69` | `OpenAICompatibleEmbedder`，默认硅基流动 `BAAI/bge-m3`，批量 `embed_documents` |
| 存储 | `vector_store.py:47-103` | Chroma 三个独立 collection：`user_private` / `user_history` / `public`；写入带 `{source, page}` metadata |
| 检索 | `retriever.py:46-48` | 私有库 top_k + **L2 距离阈值 1.0** 过滤 |
| 回退 | `retriever.py:51-74` | 私有库 → 个人沉淀库 → 公共库，返回 `(chunks, hit_private)` |

### 6.2 上传与下载

**源码**：`src/agent/rag/upload_store.py`

- uuid 做文件名，彻底避免同名覆盖和路径穿越；
- sha256 内容去重；
- `upload_id` 用正则校验，挡住 `../`；
- json 元数据原子替换写入（`upload_store.py:56-62`）；
- 原文件保留在 `data/uploads/`，供历史列表和下载。

对应接口：

- `POST /ingest`：解析 → 分块 → 向量化 → 写库 + 保存原件；
- `GET /ingest/history`：上传历史；
- `GET /ingest/history/{id}/download`：下载原 PDF。

### 6.3 防编造设计

- 检索为空：`rag_search` 返回「（无课件依据）未在课件库中检索到相关内容，请据实说明未找到」；
- 未命中私有库但命中回退库：返回时加提示头，让模型知道「不是课件原文」。

### 8.2 工程细节

| 机制 | 位置 | 说明 |
|---|---|---|

| 并发闸门 | `task_gate.py:23-30` | 进程级非阻塞锁，忙时立即 429「别人正在使用，请你稍后」 |

## 十二、源码里值得注意的几处问题

1. **防死循环没有真正生效**
   - `iteration_count` 只在入口初始化为 0，全项目没有任何地方自增；
   - `should_continue` 也不读它；
   - 当前实际兜底的是 LangGraph 的 `recursion_limit`（chat 未显式设置，默认 25；plan 设为 60）。

2. **答案溯源未闭环**
   - 入库时给每个 chunk 打了 `{source, page}` metadata；
   - 但 `ChromaVectorStore.search` 只返回 `text` 和 `distance`（`vector_store.py:77-88`）；
   - retriever 和 `rag_search` 也没把 metadata 带出来，所以「哪份资料、第几页」目前无法展示。

3. **LLM 工厂忽略配置**
   - `config.py` 读了 `DEEPSEEK_MODEL / BASE_URL`；
   - 但 `get_llm()` 直接 `init_chat_model("deepseek-flash")`（`factory.py:33`），配置项并未生效。

4. **长期记忆未接线**
   - `save_experience / recall_experience` 没有调用点；
   - 对话过程中不会沉淀，也不会召回经验。

5. **上传去重只看记录**
   - sha256 命中就直接返回旧记录；
   - 不检查向量库里对应片段是否还在。若 chroma 目录清空而上传记录保留，重新上传同一文件不会重新入库。

6. **历史列表有扫描上限**
   - 会话列表只扫最近 500 条 checkpoint；
   - 每次调用都重新 `get_checkpointer()` 开新 SQLite 连接；
   - 会话量很大时可能漏掉更早的会话。

7. **回退来源文案不精确**
   - 命中公共库时 `hit_private=False`；
   - 但 `rag_search` 统一提示「来自个人沉淀库」（`safe_tools.py:113`），公共库片段也会被这样标注。

## 十三、面试可讲的三条主线

### 主线 1：手写编排，而不是调包

- 自己实现 ReAct 的 `agent ↔ tools` 循环和条件边，而不是 `create_react_agent`；
- 自己实现 Plan-and-Execute 的 planner / dispatcher / executor / replan 四节点；
- 同一套 ReAct 底座通过 `system_prompt` 复用于 4 个子 Agent。

**可讲点**：State 的 reducer 语义、条件边路由、子图复用与缓存、为什么不用预封装。

### 主线 2：任务失败的防御链

- 计划层：结构化校验 + 错误回喂重试 + 确定性兜底计划；
- 执行层：子任务失败局部重规划，保留已成功部分；
- 预算层：`MAX_PLAN_RETRIES=3`、`MAX_REPLAN=2`，超限放弃剩余任务收尾；
- 框架层：`recursion_limit` 兜底。

**可讲点**：为什么「失败分类」比「无脑重试」重要；局部重规划相比整体重跑省了什么。

### 主线 3：RAG 的数据隔离与防编造

- 三层 collection：私有课件 → 个人沉淀 → 公共库；
- 逐级回退 + `hit_private` 标记；
- 检索为空时明确告知模型「无课件依据」，从机制上抑制幻觉；
- 上传侧 sha256 去重、uuid 文件名、路径穿越防护、原子写元数据。

**可讲点**：chunk/overlap 怎么选、L2 阈值怎么定、为什么「检索不到」也要作为一种结果返回。
